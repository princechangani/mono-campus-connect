Dependency rule
domain → port → usecase → adapter/transport
Inner layers never import outer layers. domain has zero external imports.
One file per use-case
enroll_student.go does one thing. Adding a new behaviour = add a new file, not edit an existing one.
Open/closed in practice.
Adapters are swappable
smtp.go and sendgrid.go both implement Mailer. Swap in container.go — zero usecase changes.
Liskov + Dependency Inversion.
Narrow interfaces
port/repository/student.go is its own file. A use-case only receives the interfaces it actually calls.
Interface segregation in practice.
